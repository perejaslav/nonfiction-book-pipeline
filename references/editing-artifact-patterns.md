# Editing Artifact Patterns — детальный разбор

## 1. `||` — двойная вертикальная черта

**Откуда берётся:** LLM-патчер вставляет `||` в два принципиально разных контекста.

### Тип A: Механическая склейка (истинный шов)

**Контекст появления:** LLM склеил конец одного сгенерированного фрагмента с началом следующего. Текст обрывается на границе предложения или слова, и сразу начинается новый.

**Пример:**
```
...получал легитимность именно от него.||Конфликт Набонида
```

**Лечение:** заменить `||` на `. ` (точка + пробел) или просто на пробел, если контекст позволяет.

**Признак Type A:** `||` стоит между двумя логически независимыми фрагментами, где начало второго начинается с заглавной буквы (новое предложение).

### Тип B: Внутренние разделители внутри абзаца

**Контекст появления:** LLM встраивает три-четыре дополнительных информационных блока внутрь уже написанного длинного абзаца. Вместо того чтобы интегрировать мысль, вставляет её как отдельный фрагмент, отделяя `||`.

**Пример (три `||` внутри одного абзаца):**
```
В этом и заключался главный политический смысл цилиндра. Кир не предлагал «свободу»...||Стоит присмотреться к конкретным формулировкам текста. Фраза...||Ещё один важный пассаж — список народов...||Особое место занимает рассказ о возвращении культовых статуй.
```

**Лечение:** `||` → `. ` (точка + пробел), но с проверкой, что начало следующего фрагмента образует грамматически полное предложение. Если начало потеряло связь с предыдущим текстом (например, шла склейка начала предложения) — восстановить полную формулировку вручную.

**Признак Type B:** три и более `||` в одном абзаце; каждый фрагмент после `||` начинается с заглавной буквы и представляет собой отдельное законченное предложение или несколько предложений.

### Как отличить

```
grep -n '||' manuscript.md
# Если в одном абзаце 3+ || — Type B (внутренние разделители)
# Если каждый || между двумя разными параграфами — Type A (механическая склейка)
```

### Python-диагностика для определения типа

```python
import re

def classify_pipe_doubles(path):
    with open(path) as f:
        lines = f.readlines()

    in_paragraph = []
    paragraph_pipes = []

    for i, line in enumerate(lines, 1):
        stripped = line.strip()
        if stripped.startswith('#') and not stripped.startswith('##'):
            # New top-level heading = new paragraph boundary
            if paragraph_pipes:
                count = len(paragraph_pipes)
                ptype = "TYPE_B (internal dividers)" if count >= 3 else "TYPE_A (glue seam)"
                print(f"  Paragraph at lines {paragraph_pipes[0]['line']}-{i-1}: {count} pipes → {ptype}")
            paragraph_pipes = []
        elif '||' in line:
            paragraph_pipes.append({'line': i, 'count': line.count('||')})
        elif paragraph_pipes and stripped == '':
            # Empty line = paragraph break
            if paragraph_pipes:
                count = sum(p['count'] for p in paragraph_pipes)
                ptype = "TYPE_B" if count >= 3 else "TYPE_A"
                print(f"  Paragraph: {count} pipes → {ptype}")
            paragraph_pipes = []

    return paragraph_pipes
```

### Важно: при замене `||` на `. ` теряется начало предложения

**Проблема:** Если old_string в `patch(mode=replace)` начинается НЕ с начала предложения (например, обрезана середина), то при замене `||текст` → `. Текст` начало `. Текст` может оказаться в воздухе — часть предложения потеряна.

**Признак после патча:** `grep -n '||' manuscript.md` → 0, но в файле появился оборванный текст без начала.

**Протокол:**
1. После КАЖДОГО патча с `||` делать `grep -n '||' manuscript.md` для проверки
2. Если `||` исчез, но соседние строки выглядят оборванно — перечитать ±5 строк
3. Восстановить полную формулировку через второй patch

**Пример из сессии:**
```
# Исходный текст после patch:
чужеземца.
они должны были увидеть...  ← потеряно начало!

# Исправление:
чужеземца.

В этом и заключался главный политический смысл цилиндра. Кир не предлагал...
```

## 2. `medium confidence` — служебный хвост в тексте

**Откуда берётся:** из facts.json в момент фактчекинга. Субагент забыл убрать служебную маркировку.

**Типичный паттерн:**
```
Какое бы объяснение мы ни приняли, факт остаётся фактом: греческий портрет Камбиса не подтверждается египетскими данными.  — утверждение ... имеет статус medium confidence. Это не значит, что данные ненадёжны...
```

**Лечение:** переписать в человеческую редакторскую оговорку. Не просто удалять `medium confidence`, а превратить в текст, который звучит как редакторское примечание, а не как внутренняя пометка.

**Правильная замена:**
```
Какое бы объяснение мы ни приняли, факт остаётся фактом: греческий портрет Камбиса не подтверждается египетскими данными в полном объёме. Это не значит, что данные ненадёжны; это значит, что окончательная интерпретация остаётся спорной.
```

**Регулярка для поиска:**
```
grep -in 'confidence' manuscript.md
```

**Важно:** не все `confidence` — артефакты. Встречается в контексте `data confidence`, `model confidence` (современные термины) — эти не трогать.

## 3. `страница Клита` → `эпизод с Клитом`

**Откуда берётся:** субагент использовал нестандартный оборот, не проверив в entities.md или terms.md.

**Лечение:** поиск и замена на стандартный оборот.

**Регулярка:**
```
grep -n 'страница Клита' manuscript.md
```

**Стандартный оборот:** `эпизод с Клитом` (убийство Клита — исторический термин, не «страница»).

## 4. `patch` теряет начало предложения — pitfall

**Проблема:** `patch(mode=replace)` работает с точным совпадением строки. Если old_string находится в середине предложения (не с начала), и new_string короче old_string, то текст после new_string может оказаться отделённым от контекста.

**Симптомы:**
- После patch пропали `||`, но соседний текст оборван
- grep показывает 0 `||`, но файл выглядит «криво»

**Протокол после каждого patch с `||`:**
1. `grep -n '||' manuscript.md` → 0?
2. Перечитать ±5 строк вокруг места патча
3. Если текст оборван — восстановить через второй patch с полной формулировкой

**Лучшая практика:** всегда читать old_string с запасом — начинать с начала предложения, а не с середины.

## 5. Чеклист финальной проверки после всех патчей

```bash
echo "=== || ===" && grep -c '||' manuscript.md
echo "=== medium ===" && grep -ic 'medium confidence' manuscript.md
echo "=== страница Клита ===" && grep -ic 'страница Клита' manuscript.md
echo "=== fact_ ===" && grep -c 'fact_' manuscript.md
echo "=== word count ===" && wc -w manuscript.md
```

Все значения должны быть 0 (или 0 для word count-специфичных артефактов).
